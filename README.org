#+TITLE: Lisp-RPC

Lisp-RPC is a lightweight, S-expression-based Remote Procedure Call protocol designed for simplicity and flexibility. It supports two primary modes of operation to balance dynamic communication with type safety and performance.

Other implements:

+ Lisp version: [[https://github.com/ccqpein/lisp-rpc.cl][lisp-rpc.cl]]

* Overview

Similar to JSON-RPC, Lisp-RPC defines data structures using Lisp S-expression syntax.

Key advantages:

- *Formal API contract (like gRPC)*: APIs can be formally defined using schema files (Spec Mode) to generate typed client/server code.
- *Human-readable (like JSON)*: Messages are written in plain text, making them fully readable and easy to inspect.

Key disadvantages avoided:

- *No verbose nesting (unlike JSON)*: Lisp-RPC natively supports nested structures with clean S-expressions, avoiding JSON's verbose braces and brackets.
- *No protocol boilerplate (unlike JSON-RPC)*: It does not mandate boilerplate fields like ~id~ or ~result~ at the protocol level.
- *No custom IDL language (unlike gRPC)*: It does not require learning a custom syntax (such as ~.proto~); schemas are defined using Lisp's native S-expression format.

** Two Modes

- *Plain Mode*: For direct, dynamic communication using raw S-expressions.
- *Spec Mode*: For schema-defined, type-checked communication with automatic code generation.

* Data Types

Lisp-RPC supports standard Lisp-like data structures:
- *Primary Types*: =string=, =number=, =boolean= (represented by =T= and =NIL=).
- *Complex Types*:
  - *Data*: Named structures with keyword-value pairs: =(name :key value)=.
  - *List*: Quoted sequences: ='(1 2 3)=.
  - *Map*: Anonymous keyword-value pairs: ='(:key value)=.

* Usage Modes

** Plain Mode
In Plain Mode, clients send raw S-expressions as strings. The server parses these expressions dynamically.
#+begin_src lisp
  (get-book :title "The Hobbit" :year 1937)
#+end_src

** Spec Mode
Spec Mode uses a formal schema defined with =def-msg= and =def-rpc=. This enables generating typed libraries for various target languages.

#+begin_src lisp
  (def-msg book-info :title 'string :id 'number)
  (def-rpc get-book '(:title 'string) 'book-info)
#+end_src

* Examples

** Serialize Structure

Structures that derive ~Serialize~ and ~Deserialize~ can use ~lisp_rpc_from_str~ and ~lisp_rpc_to_str~ from ~lisp_rpc_rust_serializer~ to serialize and deserialize between the structure and the Lisp-RPC format string.

Check [[file:examples/rust/serialize-struct-to-lisprpc/][this example]] for more details.

** Handling Plain Mode

~lisp_rpc_rust_raw_data::Data~ can parse a string directly into a ~Data~ object, which can then be accessed using ~.get(keyname)~.

Check [[file:examples/rust/plain-mode-read-and-write-data/][this example]] for more details.

** Spec & Code Generation Mode

[[file:examples/rust/spec-mode-generate-lib/][spec-mode-generate-lib]] shows how to generate the Lisp-RPC library code using the generator.

** Using the Server with Custom Structures

Integrating custom structures is straightforward. If the structures derive ~Serialize~ and ~Deserialize~, you need to implement ~RPCType~ with the ~impl_to_rpc!~ macro from the [[file:server/][server lib]].

Check [[file:examples/rust/server-with-custom-structure/][this example]] for more details.
