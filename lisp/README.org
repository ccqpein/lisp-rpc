#+TITLE: Lisp-RPC (Common Lisp Implementation)

The Common Lisp implementation of ~lisp-rpc~ leverages Lisp's native S-expression syntax and dynamic metaprogramming capabilities. Because Lisp-RPC data and specs are written in S-expressions, Common Lisp can treat protocol messages directly as native code or data structures, offering fluid transitions between dynamic messaging and formal contract enforcement.

* Overview & Design

In Common Lisp:
- *Native S-Expression Mapping*: Lisp-RPC messages are native Lisp S-expressions. They can be read directly via ~read-from-string~ or processed through CLOS methods.
- *Function Call Equivalence*: Any Lisp-RPC request like ~(get-book :title "The Hobbit")~ matches standard Common Lisp keyword function call syntax:
  #+begin_src lisp
    (defun get-book (&key title)
      ;; Handle request body
      )
  #+end_src
  This means simple endpoints can evaluate incoming calls directly:
  #+begin_src lisp
    (eval (read-from-string "(get-book :title \"The Hobbit\")"))
  #+end_src
- *Formal Contract Enforcement*: For production applications, explicit parsing, type checking, struct reconstruction, and contract validation are provided via *Plain Mode* and *Spec Mode*.

* Usage Modes

** Plain Mode

Plain Mode provides dynamic parsing and serialization of raw S-expressions without requiring pre-compiled schemas.

*** 1. Dynamic Parsing (~raw-data.lisp~)
Parse raw S-expression strings into ~raw-data-struct~ AST objects:

#+begin_src lisp
  (use-package :lisp-rpc-raw-data)

  (defparameter *ast* (parse-data "(book-info :title \"The Hobbit\" :id 1)"))
  ;; => #S(RAW-DATA-STRUCT :NAME BOOK-INFO :PLIST (:TITLE "The Hobbit" :ID 1))

  ;; Access fields via property list
  (getf (raw-data-struct-plist *ast*) :title) ; => "The Hobbit"
#+end_src

*** 2. Serialization & Deserialization (~common.lisp~)
Convert Common Lisp objects to Lisp-RPC format strings and vice-versa:

#+begin_src lisp
  (use-package :common)

  ;; Serialize primitives, lists, and structs
  (to-lisp-rpc-data "hello")                           ; => "\"hello\""
  (to-lisp-rpc-data 42)                                ; => "42"
  (to-lisp-rpc-data '(1 2 3))                          ; => "'(1 2 3)"

  ;; Deserialize Lisp-RPC strings directly into CLOS struct instances
  (defstruct authors names)
  (from-lisp-rpc-data "(authors :names '(\"a\" \"b\" \"c\"))")
  ; => #S(AUTHORS :NAMES ("a" "b" "c"))
#+end_src

** Spec Mode & Code Generation

Spec Mode uses formal schema specifications (~def-msg~ and ~def-rpc~) to generate typed Common Lisp project files (ASDF system and ~lib.lisp~).

*** 1. Defining a Spec (~spec-demo.lisp~)

#+begin_src lisp
  (def-rpc-package demo)

  (def-msg language-preference :lang 'string)
  (def-msg book-info :lang 'language-preference :title 'string :version 'string :id 'string)

  (def-rpc get-book
    '(:title 'string
      :version 'string
      :lang '(:lang 'string :encoding 'number)
      :authors '(:names '(list 'string)))
    'book-info)
#+end_src

*** 2. Generating the Lisp Project

You can generate project files programmatically or via the CLI tool ~lisp-rpc-gen~:

**** Programmatic Generation:
#+begin_src lisp
  (lisp-rpc-generator:generate-project "spec-demo.lisp" "./generated-demo/")
#+end_src

**** CLI Tool (~lisp-rpc-gen~):
Build the CLI tool using ~make.sh~:
#+begin_src shell
  ./make.sh
  ./lisp/lisp-rpc-gen generate -s spec-demo.lisp -o ./generated-demo/
#+end_src

This produces ~demo.asd~ and ~lib.lisp~ containing:
- ~defstruct~ definitions for messages and RPC requests.
- ~to-lisp-rpc-data~ CLOS methods.
- Contract methods for endpoint validation:
  - ~(defmethod rpc-endpoint-p ((req get-book)) t)~
  - ~(defmethod rpc-response-type ((req get-book)) 'book-info)~

** RPC Server (~rpc-server.lisp~)

The Common Lisp RPC server runs on **Woo** (an asynchronous, high-performance HTTP server built on libev).

*** Contract Enforcement & Safety:
- *Registration Validation*: ~register-rpc-handler~ verifies at registration time that the registered RPC name implements ~rpc-endpoint-p~. Standalone data messages (~def-msg~) are rejected.
- *Runtime Response Verification*: When a request completes, the server verifies that the handler's return object matches ~rpc-response-type~ declared in the spec.

*** Server Example:

#+begin_src lisp
  (use-package :lisp-rpc-server)

  ;; 1. Initialize server
  (defparameter *server* (make-rpc-server :port 5000))

  ;; 2. Register handler (validated against rpc-endpoint-p)
  (register-rpc-handler *server* 'demo:get-book
    (lambda (req)
      ;; req is automatically deserialized into a #S(DEMO:GET-BOOK ...) struct
      (demo:make-book-info
       :title (demo:get-book-title req)
       :id "12345")))

  ;; 3. Start server
  (start-server *server*)
#+end_src
